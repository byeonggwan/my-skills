# 결정 대기함 만들기

## 개요

> **REQUIRED (2026-10 디자인 시험 운영):** 페이지의 보이는 모양은 `designing-with-uupm-and-shadcn` 스킬을 따른다(틀은 ui-ux-pro-max, 구현은 shadcn). 이 스킬의 페이지 계약과 구조는 그대로 유지한다.


사용자의 답을 기다리는 결정 여러 건을 한 Artifact 페이지에 모읍니다. 사용자는 결정을 **한 화면에 하나씩** 보며 고르고, 고른 내용은 페이지 저장소(`db`)에 남습니다. 내가 그 저장소를 읽어 결정을 기다리던 쪽에 전달합니다.

이 스킬의 템플릿은 `template.html` 하나입니다. **BOARD와 ITEMS 블록만 채웁니다.** 레이아웃, 저장, 요약, 복사 대체 경로는 템플릿에 이미 들어 있습니다.

## 완성된 페이지의 모습

| 부분 | 내용 |
| --- | --- |
| 왼쪽 목록 | 결정마다 짧은 이름, 이슈 이름(번호), 대기/결정함 표시. 맨 아래에 "선택 요약". 좁은 화면에서는 위쪽 탭 줄 |
| 결정 화면 | 이슈 이름 · n/N → 질문 한 문장(h1) → 맥락 2~4줄 → 선택지 카드 → 내 의견 → 메모 → 접이식 "더 알아 두면 좋은 내용" → 이전 / 저장하고 다음 |
| 선택지 카드 | 출처 배지(세션 권장안·Codex 권장안·대안), 내가 추천하는 카드에 "<내 이름> 추천" 배지, 제목 한 줄, 요점 목록, 트레이드오프 한 문장. 맨 끝에 "다른 의견"(메모 필수) |
| 선택 요약 | 결정별 고른 안과 메모, "완료하고 반영 요청" 버튼. 버튼은 선택 요약을 댓글로 남기면서 나에게 보냄(`comments.sendToClaude`). 보낼 수 없는 상태면 이유와 함께 "대화창에 '<reply>'라고 말씀해 주세요" 안내 |
| 글자 | 본문 18px, 보조 글씨도 14px 이상. 카드를 나란히 두지 않고 세로로 쌓기 |

## 순서

1. **질문 원문 확인.** 기억이나 요약으로 쓰지 않습니다. 결정을 기다리는 세션의 마지막 답변을 transcript에서 읽습니다.
   - 위치: `~/.claude/projects/<작업 디렉터리의 / 를 - 로 바꾼 이름>/` 안에서 가장 최근 `.jsonl`. 워크트리 세션이면 워크트리 경로 기준 디렉터리입니다.
   - 큰 파일이므로 python으로 마지막 `type == "assistant"`의 text 블록만 뽑습니다. `isSidechain`이 참인 줄은 건너뜁니다. 그 뒤에 사용자 메시지가 없어야 아직 답을 기다리는 상태입니다.
   - 서브에이전트라면 그 결과 전문을 봅니다.
   - 선택지, 근거, 트레이드오프를 원문에서 옮깁니다. 원문에 없는 안(예: Codex 안)은 지어내지 않고 그 카드를 뺍니다.
2. **ITEMS 채우기.** 템플릿의 예시 항목은 지우고 실제 결정으로 바꿉니다. `<title>`, BOARD.title, BOARD.subtitle도 바꿉니다.
   - 결정 하나가 항목 하나입니다. 한 메시지에 질문이 둘이고 따로 고를 수 있으면 항목을 나눕니다. 둘째 질문이 첫째 답을 전제로 하면(예: "계획을 승인한다면 실행 방식은?") 한 항목으로 묶고, 맥락에 "모든 안이 앞 질문의 승인을 뜻한다, 아니면 '다른 의견'"이라고 적습니다.
   - `id`와 `options[].key`는 영문·숫자입니다. `id`는 저장소 문서 id가 됩니다.
   - `short`에는 이슈 번호만 쓰지 않고 무슨 일인지 씁니다.
   - 내가 추천하는 선택지에 `mine: true`, `mineText`에 이유 한두 문장.
   - 선택지끼리 구조가 다를 때만(배포 순서, 호출 흐름, 화면 배치처럼 그림으로 보면 바로 갈리는 경우) 각 선택지에 `figure`(인라인 SVG 문자열)와 `figureCaption`(한 문장)을 넣는다. 같은 도식 모양으로 그려서 선택지끼리 비교되게 하고, 그리는 기준은 `designing-with-uupm-and-shadcn`의 "도식과 인포그래픽"을 따른다. SVG는 `width="280"`(viewBox 폭도 280) 이하로 그린다. 400px 화면의 선택지 카드 안쪽 폭이 약 280px이라 그보다 넓으면 줄어들면서 글자가 14px 아래로 작아진다. 글로 충분한 결정에는 넣지 않는다.
3. **처음 게시.** 템플릿을 scratchpad에 복사해 채우고, 글꼴 파일(`~/.claude/skills/designing-with-uupm-and-shadcn/fonts/PretendardVariable.woff2`)을 복사본 옆 `fonts/`에 복사한 뒤 게시합니다.
   ```
   Artifact publish: file_path=<복사본>, icon="checklist",
     capabilities={"db": {}, "user": {}, "comments": {}}, description=<한 문장>,
     files={"fonts/PretendardVariable.woff2": "<복사본 폴더>/fonts/PretendardVariable.woff2"}
   ```
   `db`가 없으면 저장이 되지 않고, 페이지는 복사 버튼으로 대체합니다. `comments`가 없으면 완료 버튼이 꺼집니다.
4. **한 번만 확인.** `ArtifactData list collection="decisions"`를 읽습니다. `ArtifactComments watch`(url 없이)로 이 대기함 줄이 "auto-replies armed"인지 봅니다. 아니면 완료 버튼이 나에게 닿지 않으므로, 사용자에게 "대화창에 '<reply>'라고 말씀해 주세요"로 안내합니다. 사용자에게 링크, 화면 구성, "다 고르면 선택 요약의 완료 버튼을 눌러 주세요"를 알립니다.
5. **완료 버튼 댓글(`[Artifact comment sent to Claude]`, 첫 줄이 "<reply>")이 오거나 사용자가 "<reply>"라고 하면** 댓글 본문은 참고만 하고, 반드시 `ArtifactData list collection="decisions"`를 읽고 **지금 ITEMS에 있는 id만** 봅니다. 문서마다 `choice`, `note`, `savedAt`이 있습니다. 결정을 기다리던 쪽에 고른 안과 메모를 그대로 보냅니다. `choice`가 `other`이거나 메모에 질문이 있으면 그 건만 사용자에게 먼저 확인합니다. 전달한 결정은 다음 갱신 때 ITEMS에서 뺍니다. 댓글로 왔으면 그 스레드에 "무엇을 어느 세션에 전달했는지"를 `ArtifactComments reply`로 짧게 답하고 `resolve`합니다. 사용자에게 확인할 건이 남았으면 resolve하지 않고 대화창에서 묻습니다.
6. **이미 있는 대기함 갱신.** 새 페이지를 만들지 않고 같은 URL을 씁니다.
   - 이 대화에서 게시한 파일이면 같은 `file_path`로 다시 게시합니다.
   - 다른 대화에서 만든 대기함이면 `Artifact list`로 URL을 찾고 `Artifact read`로 읽은 뒤, 그 내용을 고쳐 `url`을 넘겨 게시합니다.
   - 다시 게시할 때는 `icon`과 `capabilities`를 **넘기지 않습니다**. 빼면 기존 값이 유지됩니다. 예외: `comments` 없이 만든 옛 대기함이면 한 번만 `{"db": {}, "user": {}, "comments": {}}`를 전부 다시 적어 넘깁니다(일부만 적으면 빠진 기능이 꺼집니다).
   - 저장소 정리: 같은 질문이 그대로 남아 있으면 같은 `id`를 써서 이미 고른 선택을 살립니다. 질문이 바뀌었으면 새 `id`(예: `618b`)를 씁니다. 이미 전달한 결정의 문서는 남아 있어도 ITEMS에 없으면 화면에 나오지 않습니다.

## 흔한 실수

| 실수 | 결과 | 바로잡기 |
| --- | --- | --- |
| 결정을 세로로 쌓은 스크롤 페이지 | 사용자가 비교하기 어렵다고 함 | 템플릿을 그대로 써서 한 화면에 하나씩 보여 줌 |
| 선택지 카드를 2~3열로 나란히 배치, 본문 15~16px | "글자가 작고 한 화면에 다 담으려 해서 가독성이 떨어진다"는 지적 | 세로로 쌓고 본문 18px |
| 요약본으로 선택지를 다시 씀 | 세션이 실제로 물은 것과 어긋남 | 1단계에서 원문 읽기 |
| `capabilities` 없이 처음 게시 | 선택이 사용자 브라우저에만 남아 내가 읽지 못함 | 처음 게시 때 `{"db": {}, "user": {}, "comments": {}}` |
| 완료 버튼 댓글 본문만 보고 전달 | 댓글은 버튼을 누른 순간의 화면 내용이라 그 뒤 수정이 빠질 수 있음 | 전달 직전에 저장소를 다시 읽음 |
| 갱신할 때 새 경로로 게시 | 대기함 URL이 둘이 됨 | 6단계: 같은 파일 또는 `url` |
| 템플릿 예시 항목을 남김 | "예시:" 결정이 사용자에게 보임 | 2단계에서 예시 지우기 |
| 저장할 때마다 알림이 온다고 가정 | 오지 않음 | 완료 버튼 댓글이나 사용자의 `<reply>`가 왔을 때 읽음 |
| 스크립트로 ITEMS를 바꾸다 위치 계산이 어긋나 문법이 깨짐 | 페이지가 빈 대기함으로 보임(2026-10-19 v71) | 게시 전에 마지막 `<script>` 내용을 파일로 뽑아 `node --check`로 확인. 위치(index)를 구한 뒤 다른 치환을 먼저 하지 않음 |
