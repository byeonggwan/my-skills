# 테크 스펙 작성

## Overview

테크 스펙은 **개발 직전에 사람이 이 이슈의 설계를 검토하고 승인하는 한 장**이다. 화면기획서가 "무엇을 보여 주나"라면 테크 스펙은 "어떻게 만들고, 무엇이 잘못될 수 있고, 사람이 무엇에 답해야 하나"다.

구조는 2026-10-20 사용자가 승인한 E안이다. 사용자 지시 원문: "안에 들어갈 내용은 내가 이전에 지시했던 내용이나 스킬에 있는거 완전히 무시하고, 처음부터 해보자. 단 시각화나 flowchart같은 것은 필요하니까 그건 기억하고.. 테크 스펙에 대해 자세히 조사하고, 들어갈 내용들을 나열한 뒤에 어떻게 해야 이 디자인에 적절히 잘 얹을지 봐봐" → E안 검토 후 "적절한거같음. 이런 방식으로 스킬 변경".

절 구성은 업계 테크 스펙(해외 14곳, 국내 3곳 조사)에서 빈도가 높은 절을 따른다: 배경, 목표·비목표, 설계, 검토한 대안, 위험, 열린 질문, 출시 계획, 테스트. 디자인은 사용자가 고른 D안(네이비 머리, 호박색 상태 띠, 왼쪽 목차와 건수, 펼쳐 보는 한 줄 목록, 시점별 색)이다.

줄글은 최후의 방편이다(사용자 지시 2026-10-19). 관계는 흐름도로, 상태는 상태도로, 비교는 같은 모양 두 줄로, 위험은 격자로, 순서는 타임라인으로 보여 준다.

## 이전 형식과 다른 점

옛 "확인·결정할 것"은 열린 질문, 받아들인 위험, 이미 정한 결정, 선행 의존을 한 목록에 같은 모양으로 섞어서 사용자가 "맘에 너무 안 든다"고 했다. 이제 넷을 다른 절에 둔다.

| 항목 | 가는 곳 | 가르는 기준 |
| --- | --- | --- |
| 사람이 골라야 답이 나오는 것 | 6 열린 질문 · 검토 중 | 선택지가 둘 이상이고 제품 동작이나 비용이 바뀐다 |
| 실제로 해 봐야 아는 사실 | 6 열린 질문 · 구현 중 | 외부 API 응답, 권한, 실측 시간처럼 설계가 기대는 가정 |
| 다음 단계에서 정해도 되는 것 | 6 열린 질문 · 다음 단계 전 | 지금 답하지 않아도 이번 단계 구현이 바뀌지 않는다 |
| 정했지만 대가가 있는 것 | 4 검토한 대안 | 고른 안, 버린 안, 대가 |
| 정했지만 잘못될 수 있는 것 | 5 위험과 대응 | 영향·가능성·대응·감지. 받아들인 위험도 여기 |
| 다른 팀이나 다른 이슈가 먼저 끝내야 하는 것 | 7 출시 계획 · 선행 | `stage pre` |

사용자가 이미 정한 것은 질문으로 올리지 않는다. 대안 카드의 채택으로 쓴다.

## 입력 (순서대로)

1. 설계 원본: 워크트리의 `docs/superpowers/specs/*<이슈키>*`. 결정, API, 데이터, 마이그레이션, 실패 처리를 옮긴다.
2. 화면기획서: `Artifact read`로 읽는다. 화면 요구가 설계에 없거나 다르면 열린 질문(검토 중)으로 올린다.
3. 결정 상태: 프로젝트 메모리와 결정 대기함에서 사용자가 이미 정한 것과 기다리는 것을 가른다.
4. 코드: 설계 원본이 기존 코드를 전제로 하는 부분만 확인한다. 원본과 코드가 다르면 열린 질문이나 위험으로 올린다.

없는 내용은 지어내지 않는다. 원본에 답이 없으면 그 자체가 열린 질문이다.

## 페이지 계약 (템플릿 순서 그대로)

| 부분 | 규칙 |
| --- | --- |
| 머리 | "테크 스펙" → `이슈 이름 (이슈 키)`, 이슈 키는 항상 Jira 이슈 링크(새 탭, 왼쪽 목차 위 이슈 키도 같은 링크. 2026-10-20 사용자 요청, 검사기가 본다) → 세 줄 요약(무엇을 · 왜 · 어떻게, 각 한 문장) → 문서 상태 단계(초안 · 검토 중 · 승인 · 구현 중 · 완료, 지금 단계 하나) → 링크 칩(화면기획서, 관련 Jira 이슈만) |
| 상태 띠 | 검토 중 질문이 있으면 호박색 `state` "검토 후 개발". 없으면 초록 `state go` "개발 가능". 진행을 멈춰야 하면 빨강 `state hold` "보류". 조건 한 문장. 건수 칩(검토 중 질문, 구현 중 확인, 다음 단계 전 질문, 위험, 선행 작업)은 0건이면 뺀다 |
| 왼쪽 목차 | 절 9개와 건수, 아래에 질문 시점 묶음 건수. 템플릿 스크립트가 현재 절을 강조한다 |
| 1 배경과 문제 | 2~3문장 + 구체 사례. 요청 원문이 목록이면 `asks`. **지금과 바뀐 뒤를 같은 모양 두 줄**로 비교하고 바뀌는 칸만 강조 |
| 2 목표와 비목표 | 세 칸. 목표(확인할 수 있는 결과, `goal-N`), 비목표(이번에 안 하는 것, 다른 이슈면 번호), 절대 일어나면 안 되는 것(`never-N`, 테스트로 지킬 것) |
| 3 설계 | 핵심 경계 한 문장 → 3.1 처리 흐름(mermaid) → 3.2 상태도(상태가 바뀌는 대상이 있을 때만) → 구성 요소 카드(신규·변경, Q·R 링크) → API 표(메서드·신규/변경·호출자, 예시는 펼침) → 데이터 변경(컬렉션 카드, 마이그레이션·인덱스·크기 칩) → 배치(서버별 프로세스 카드 + 처리량·비용 한두 문장). 해당 없는 하위 절은 "해당 없음: 이유" |
| 4 검토한 대안 | 결정 하나에 카드 하나. 채택(초록, 정확히 하나, 대가 포함), 버림(회색), 나중(점선). 끝에 "이번에 뺀 것" 칩 |
| 5 위험과 대응 | 영향×가능성 3×3 격자에 R 점, 오른쪽에 위험 목록(펼치면 영향·대응·감지). 한 항목에 위험 하나 |
| 6 열린 질문 | 시점별 세 묶음: 검토 중(보라, 선택지·추천·틀리면) / 구현 중(파랑, 확인 방법과 결과별 처리) / 다음 단계 전(청록, 배경·추천). 제목은 질문 문장(?로 끝남). 답할 사람 칩. 빈 묶음은 지운다 |
| 7 출시 계획 | 타임라인: 선행(`stage pre`, 호박), 바탕 이슈(`stage base`, 보라), 이번 단계(`stage`, 파랑), 다음 단계(`stage next`, 청록). 담당 칩. 아래에 번호 붙은 배포 순서와 되돌리기 |
| 8 테스트와 성공 기준 | 성공 기준 한 문장 상자 + 검증할 동작 체크리스트. 동작마다 지키는 목표·절대 안 됨·위험·질문·대안 링크 |
| 9 예상 Q&A | 운영자·교수자·다른 개발자가 물을 법한 것, 답은 한두 문장 |

번호: 열린 질문은 문서 전체에서 Q1부터, 위험은 R1부터 순서대로. 다른 절에서 `href="#Q3"`, `href="#R2"`로 가리킨다. 펼친 항목 안을 가리켜도 템플릿 스크립트가 펼쳐서 이동한다.

## 흐름도와 상태도

mermaid 원문은 `<script type="text/plain" class="flow-src">`에 넣는다. 템플릿 렌더러가 원래 크기(16px)로 그리고, 넘치면 상자 안에서만 스크롤하며, "크게 보기"를 붙인다. 색은 렌더러가 토큰으로 칠하므로 원문에 색 값을 쓰지 않는다.

| 대상 | 쓰는 법 |
| --- | --- |
| 실행 주체 묶음 | 주체(화면·API, cron, worker, 외부 서비스)마다 `subgraph`. 첫 줄에 `%% group SET=violet CRON=blue WK=teal` |
| 상자 색 | `:::violet` `:::blue` `:::teal`(주체 색, 묶음과 같게), `:::amber`(판단), `:::bad`(실패 결과), `:::ok`(성공 결과), `:::ext`(기존·저장소·외부) |
| 화살표 | `==>` 정상 경로(초록 굵게), `-.-x` 실패·아니오(빨간 점선), `-.->` 읽기(회색 점선), `-->` 그 밖 |
| 상태도 | `stateDiagram-v2`, 상태 id는 공백 없는 한글, 표시 이름은 `id: 이름`. `%% paint 추가됨=ok 실패함=bad 업로드중=amber 대상아님=ext`로 색 |
| 범례 | 도식 아래 `flow-legend`에 쓴 색만. 묶음 색 `lg violet/blue/teal`, `lg ext`, `lg dec`(판단), 선 세 종류 |
| 라벨 | 상자 2줄 이내(`<br>`), 선 라벨은 실제 값이나 조건("예", "실패", "Redis 큐", "500개씩") |

## 만드는 순서

1. `template.html`을 scratchpad의 새 폴더 `index.html`로 복사한다. `{{ }}` 자리표시자와 `<!-- 안내: -->` 주석을 모두 실제 내용으로 바꾸거나 지운다. 예시 항목 개수는 내용대로 늘리고 줄인다. `{{이슈 주소}}`는 프로젝트 부록(CLAUDE.md나 프로젝트 메모리)에 적힌 이슈 트래커 주소로 채우고, 부록에 없으면 사용자에게 묻는다. 이 문서 전용 CSS가 필요하면 `<style>` 끝에 모은다.
2. 검사: `node ~/.claude/skills/writing-tech-specs/check-techspec.mjs <file>` 오류 0. Atlassian이 아닌 이슈 트래커를 쓰면 `TECHSPEC_TRACKER_HOSTS=host1,host2`로 허용 호스트를 넘긴다. 자리표시자, 절 순서, 링크 대상, 질문·위험 번호와 필드, 띠·목차·묶음 건수, 상태 단어와 질문의 일치, 격자 점, 대안 채택 수, 외부 스크립트, 작성 과정 메타를 본다.
3. 미리보기: `--preview <폴더>/_preview.html`로 감싼 파일을 만들고, 폴더에 `fonts/`를 복사한 뒤 scratchpad에서 `python3 -m http.server`를 띄운다(snap Chromium은 `/tmp`를 `file://`로 못 읽는다). `chromium --headless=new --no-sandbox --hide-scrollbars --virtual-time-budget=20000 --window-size=1280,9000 --screenshot=<홈 아래 경로>`로 1280·375 폭을 본다. 흐름도를 크게 보려면 `.hero,.state,.rail,#background,#goals{display:none}`를 넣은 사본을 캡처한다(해시로 스크롤한 캡처는 빈 화면이 나온다). 가로 넘침은 `document.documentElement.scrollWidth`로 확인한다(headless 창은 최소 500px).
4. 발행: 글꼴을 `<폴더>/fonts/`에 복사하고 `Artifact publish`(`icon: "blueprint"`, `label: <이슈 키>`, description 한 문장, 첫 발행이면 `files={"fonts/PretendardVariable.woff2": "<폴더>/fonts/PretendardVariable.woff2"}`).
5. Jira 댓글(처음 발행 때 한 번, 묻지 않음): 본문은 `테크 스펙: <이슈 이름>` 한 줄과 URL 한 줄. 이미 같은 URL 댓글이 있으면 달지 않는다. Jira 쓰기를 조율 세션이 맡는 프로젝트면 조율 세션에 요청한다.
6. 회신: URL + 상태 단어 + 검토 중 질문 제목 목록. 검토 중 질문은 프로젝트 규칙대로 결정 대기함에도 올렸는지 함께 알린다.

## 개정할 때

같은 URL에 다시 발행한다. 답이 난 질문은 지우고 그 내용을 대안(채택)이나 설계에 반영한다. 번호는 다시 매기고 링크와 건수를 맞춘다(검사기가 본다). 문서 상태 단계를 옮긴다. 개정 이력은 문서에 쓰지 않는다.

## 문서에 넣지 않는 것

작성 과정(누가 리뷰했는지, Codex·세션 의견, 리뷰 횟수), 원본 경로·커밋, 결정 대기함 링크. 리뷰가 찾은 문제는 문제 그 자체로 위험이나 질문에 쓴다. 업계 양식에도 이런 메타 절은 없다. 링크는 화면기획서와 Jira만 둔다.

## Common Mistakes

| 증상 | 고치는 법 |
| --- | --- |
| 정한 결정을 열린 질문에 다시 올림 | 대안 카드의 채택으로 옮긴다 |
| 받아들인 위험을 질문으로 물음 | 위험 절에 "대응: 받아들인다"로 쓴다. 바꿀지 물을 이유가 있으면 그때만 질문 |
| 구현 중 확인할 사실 때문에 "검토 후 개발" | 상태 단어는 검토 중 질문만 본다 |
| 한 위험 항목에 여러 위험 | 나눈다. 격자 점도 하나씩 |
| 흐름도에 classDef·linkStyle·hsl을 직접 씀 | `:::색`, `%% group`, 화살표 모양만. hsl의 쉼표는 mermaid 렌더를 깬다 |
| 상태도 색을 `class` 문으로 칠함 | 한글 id를 받지 않는다. `%% paint` |
| 위로 거슬러 오르는 엣지가 많아 선이 엉킴 | 흐름 방향대로 노드를 선언하고, 되돌아가는 선은 상태도로 옮긴다 |
| 줄글 문단이 설계 절에 길게 들어감 | 흐름도·카드·표로 옮기고 남는 것만 한두 문장 |
| 띠·목차·묶음 건수를 손으로 맞추다 어긋남 | 검사기로 확인 |
